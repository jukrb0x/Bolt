Validate `bolt.yaml`. When `bolt.local.yaml` is present, validate that too.

## Usage

```bash
bolt check
```

## Description

Validates your configuration against Bolt's schema:

- **`bolt.yaml`** — file existence, YAML syntax, `version: 1`, and the core schema
  (project name, tasks, flows, plugins). `ue` and `svn` plugin metadata is checked
  when those entries are present.
- **`bolt.local.yaml`** — only if the file exists. It may contain `vars`,
  `plugins` (per-namespace overrides), and `capabilities` (per-key overrides of
  the same map in `bolt.yaml`). `bolt.yaml` is validated after those overrides
  are merged. A missing file is not an error. An unknown capability key, a
  handler ref that does not provide that tag, `CAPABILITY_AMBIGUOUS`,
  `CAPABILITY_MISSING`, and `CAPABILITY_SELECTION_INVALID` are config errors (exit code
  `3`). Fan-out tags in `capabilities:` print one warning and are ignored.

When either file still uses bolt v2.0 keys (no `version`, root `targets`,
`project.engine`/`project.project`, or local `engine_path`, `project_path`,
`uproject`, `use_tortoise`), `bolt check` lists each key, says where it moved,
and prints the converted `bolt.yaml` and `bolt.local.yaml`. Run
[`bolt migrate`](/cli/migrate) to write them.

`bolt check` also reports any `${{ project.<key> }}` in tasks or flows other than
`${{ project.name }}`, since nothing else exists under `project`. Use a var instead.

Errors in values that come from `bolt.local.yaml` overrides are labeled
`bolt.local.yaml: plugins.<namespace>.<path>`.

Every problem is reported as a `path → message` row.

## Options

None.

## Exit Codes

| Code | Description                                             |
| ---- | ------------------------------------------------------- |
| 0    | The config is valid                                     |
| 1    | `bolt.yaml` not found, or one or more validation errors |

## Examples

```bash
# Validate configuration
bolt check

# Use in CI: only build if the config is valid
bolt check && bolt run build
```

Output when valid:

```
bolt.yaml: /path/to/bolt.yaml
✓ bolt.yaml is valid
```

Legacy task composition is intentionally rejected. Replace `uses: task/name` with `call: name`; `uses` is reserved for plugin/local actions.

Output on a schema error:

```
bolt.yaml: /path/to/bolt.yaml
✗ bolt.yaml has 2 error(s):

  version                             config version is required (expected 1)
  project.name                        Required
```
