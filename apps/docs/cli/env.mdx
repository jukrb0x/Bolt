---
title: "bolt env"
description: "Probe declared environment checks and fill required gaps."
---

`bolt env` reads the environment checks declared for this project. `probe` reports gaps. `ensure` fills required gaps. Neither command is `ue/setup`, and neither is workspace sync.

## Usage

```bash
bolt env probe [--json] [--manifest <path>]
bolt env ensure --dry-run [--json] [--manifest <path>]
bolt env ensure --execute --plan=<hash> [--confirmed-by-user] [--json] [--manifest <path>]
```

## Probe

`bolt env probe` is read-only. It does not install tools.

Checks come from `env.checks` in `bolt.yaml`, from the file named by `env.manifest`, or from `--manifest`. A path is relative to the directory that contains `bolt.yaml`. `--manifest` replaces the `env` block for that invocation.

Plugins register handlers with capability `env.check` and a stable `checkId`. Probe calls the handler whose id matches. The handler receives the declaration on `ctx.envCheck`. `ctx.envCheck.action` is unset during probe.

`data.checks` lists every result (`pass`, `fail`, `warn`, `skip`). `data.gaps` lists fail and warn rows with `id`, `current`, `expected`, and `fix`. A gap is still exit 0. `require: false` turns a failing check into `warn`, which stays in `gaps`.

Human output prints one line per check and `Fix:` for fail and warn rows. `--json` prints one `bolt.env.probe/v1` document and nothing else on stdout.

## Ensure

`bolt env ensure --dry-run` is read-only. It prints `data.plan` and `data.plan_hash` (`sha256:` plus 64 hex characters). `changed`, `noop`, and `failed` stay empty. The machine is unchanged.

`data.plan` is the environment plan. Each row is `{ id, action, will_change }` and `reason` when the action is `noop`. It is not a workspace sync plan. `bolt workspace sync` is not part of this command.

Policy is `fill-gaps`. A required gap has `action: "ensure"` and `will_change: true`. A check that already passes is `noop` / `already_satisfied`. A check with `require: false` is `noop` / `not_required` and is not installed. A skipped check is `noop` / `skipped`.

`bolt env ensure --execute --plan=<plan_hash> --confirmed-by-user` applies that plan. The hash must be the one from a fresh dry-run of the same manifest. A different hash exits 4 with `PLAN_MISMATCH` and does not change the machine. Missing `--confirmed-by-user` exits 4 with `CONFIRM_REQUIRED` and does not change the machine.

After execute, `dry_run` is false. `changed` lists check ids that were filled. `noop` lists ids that were left alone, with a reason. `failed` lists `{ id, code }` when one check could not be filled. One failure does not clear the others. Exit 1 means at least one check failed. A second ensure, with nothing broken in between, reports `summary.changed` 0.

`--json` prints one `bolt.env.ensure/v1` document.

The built-in git plugin provides `vcs.git.lfs`. It reports a missing Git LFS binary, a version below the declared constraint, or missing user filters. Ensure runs `git lfs install --skip-repo` only for the filters gap. It does not install the Git LFS package. Test plugins `fixture.tool.a` and `fixture.tool.b` can write a marker file under `.bolt/env-checks/`. That is not a one-click environment for a studio.

On the apply step, core sets `ctx.envCheck.action` to `"ensure"`. Handlers that only probe ignore that field. The handler function signature is unchanged.

## Options

| Flag                  | Command | Description                                                  |
| --------------------- | ------- | ------------------------------------------------------------ |
| `--json`              | both    | Print one JSON document. `ok` is true when the exit is 0.    |
| `--manifest <path>`   | both    | Read checks from this file instead of `bolt.yaml` `env`.     |
| `--dry-run`           | ensure  | Print the plan and `plan_hash`. Does not change the machine. |
| `--execute`           | ensure  | Apply the plan. Requires `--plan` and `--confirmed-by-user`. |
| `--plan <hash>`       | ensure  | `plan_hash` from `--dry-run`.                                |
| `--confirmed-by-user` | ensure  | User approved the plan. Required with `--execute`.           |

## Exit codes

| Code | Description                                                                                                                                            |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 0    | Probe finished, or ensure finished. Gaps may be non-empty on probe. Ensure may report `changed` 0. No declared checks is a warning, `ENV_NO_MANIFEST`. |
| 1    | A check handler threw (`RUN_FAILED`), or ensure could not fill a gap (`ENSURE_FAILED` or a plugin code such as `LFS_MISSING`).                         |
| 2    | Unknown flag, or ensure was not given exactly one of `--dry-run` or `--execute --plan`.                                                                |
| 3    | `MANIFEST_INVALID` or `CHECK_UNKNOWN`.                                                                                                                 |
| 4    | Ensure execute was refused: `PLAN_MISMATCH` or `CONFIRM_REQUIRED`. Nothing was changed.                                                                |

## Examples

```bash
bolt env probe
bolt env probe --json
bolt env probe --manifest env.manifest.yaml --json
bolt env ensure --dry-run --json
bolt env ensure --execute --plan=sha256:… --confirmed-by-user --json
```

```yaml
env:
  checks:
    - id: fixture.tool.a
      require: true
    - id: fixture.tool.b
      require: true
    - id: vcs.git.lfs
      require: false
```
