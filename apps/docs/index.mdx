Your daily GameDev workflow, automated.

Bolt is a command-line tool for the repetitive work around a game project: pulling the latest engine and
project changes, rebuilding the editor, launching it, and whatever else your team does every morning.
You describe that work once in a `bolt.yaml` at the project root, commit it, and everyone runs the same
commands.

The Bolt core does not depend on any engine. Engine-specific steps come from plugins. Bolt ships a
built-in `ue` plugin for Unreal Engine, plus `git`, `svn`, `fs`, and `json` plugins. You can write your
own plugins in TypeScript.

## Quick start

Install Bolt:

<Tabs>
  <Tab title="Windows (PowerShell)">
    ```powershell
    irm https://raw.githubusercontent.com/jukrb0x/Bolt/main/install.ps1 | iex
    ```
  </Tab>
  <Tab title="macOS / Linux">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/jukrb0x/Bolt/main/install.sh | sh
    ```
  </Tab>
</Tabs>

Open a new terminal so `bolt` is on your `PATH`. Windows installs `%USERPROFILE%\.bolt\bin\bolt.exe`.
macOS and Linux install `~/.bolt/bin/bolt`. Run `bolt self-update` to update later. See
[Installation](/guides/installation) for details.

Scaffold a config in your project and try it:

```bash
cd /path/to/your/project
bolt init              # writes bolt.yaml with a `hello` task and a `demo` flow
bolt run demo --dry-run
bolt run demo
```

`bolt init` also writes a JSON Schema for editor completion, plugin type definitions, and a
`tsconfig.json`. It does not write `bolt.local.yaml`.

## Example: a daily Unreal Engine workflow

This `bolt.yaml` updates the engine (git) and the project (svn), builds the editor, and launches it.
Unreal settings live under the `ue` plugin's `config`, not at the root of the file.

```yaml
version: 1

project:
  name: MyGame

plugins:
  - namespace: ue
    config:
      engine: { path: C:/UnrealEngine, vcs: git, branch: main }
      project: { path: C:/Projects/MyGame, vcs: svn }
      uproject: C:/Projects/MyGame/MyGame.uproject
      targets:
        editor: { kind: editor, config: development }

tasks:
  update: [{ uses: ue/update_engine }, { uses: ue/update_project }]
  build: [{ uses: ue/build, with: { target: editor } }]
  start: [{ uses: ue/start }]

flows:
  daily:
    description: Update, build, and launch the editor
    steps: [update, build, start]
    continue_on_fail: [start] # update/build failures abort; start may fail
```

```bash
bolt run update build start     # tasks, in the order typed
bolt run build --config=debug   # a param overrides the step's `with:` value
bolt run daily                  # the predefined flow
bolt run daily --dry-run        # preview the steps without executing
```

Each developer can point the engine at their own checkout in `bolt.local.yaml`:

```yaml
# bolt.local.yaml (gitignored)
plugins:
  ue:
    engine: { path: D:/UE_5.4 }
```

<Note>
  The `ue` plugin's build, launch, and kill handlers currently target Windows (`Build.bat`, `Win64`,
  `taskkill`). The `bolt` binary itself runs on Windows, macOS, and Linux.
</Note>
